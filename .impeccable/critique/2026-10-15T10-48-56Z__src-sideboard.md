## Design Specificity Verdict

The **content grammar** is authored for this product: the freshness rule (one timestamp, a state only when not fresh, identical on card and full view), the honesty vocabulary (`missing quote`, `market quote`, `priced 1/3`, `share of tracked`, `not added to Mac RAM`, `cpu (engine)`), the pin diamond, the held/focused border tiers, per-slot rotation queues with per-reason holds. None of that transfers unchanged to another dashboard.

The **layout grammar** is category-interchangeable: a stock Textual tab strip with no counts or status; six noun tabs; rounded 1-cell panels; a label-left/value-right metric grid with identical weight per metric; a fixed 90%×80% modal; raw engine tables; eleven third-party palettes as the only theming. The 30–40% black region under short cards is not a choice either — it is `apply_heights` giving every card a fixed row count and never filling the pane.

**Deterministic scan**: `impeccable detect --json src/sideboard` → `[]`, exit 0. That is an *empty scan, not a pass*: the detector's scope is HTML/CSS/DOM with a browser viewport, and this target is a terminal UI. Browser visualisation, overlay injection and live mode were skipped for the same reason. The evidence that mattered came from computed numbers instead: WCAG contrast, Rich's cell widths, and the stylesheet's sizes.

## Overall Impression

A calm, honest, keyboard-first dashboard whose visual language stops short of its own integrity model. The best thing about it is that it refuses to lie — missing is "—", price basis is on every row, engine CPU is labelled as not host CPU. The biggest opportunity is that the screen does not yet *say* the things it knows: severity is thrown away, stale cards look fresh, and the loudest element on screen is the keyboard cursor rather than a failing job.

## What's Working

1. **The honesty model is enforced and mostly visible.** Missing values are "—" and never 0; each holding row carries its price basis; RAM is labelled as a subtraction, not memory pressure. Rare in a dashboard, and the product's actual differentiator.
2. **One card shell, one freshness string.** `CardShell` owns loading/stale/held/pinned/privacy/resize for every widget, and `freshness_line` is used by both the card and `DetailScreen`, so a card and its full view can never disagree about when data arrived. The refusal of footnotes and duplicate timestamps leaves a stable reading grammar: title → metrics → list/table → one timestamp.
3. **Rotation is a real state machine.** Holds are tracked per reason, release resumes the remaining dwell after a grace period, hover repaints are coalesced, and arrows walk a card's rows before handing movement to the neighbour — the keyboard never sticks at a card edge.

## Priority Issues

**[P0] Provider text reaches a markup parser through the border chrome.** `control_free` strips control characters but keeps square brackets, and Textual's `border_title` setter runs `render_str` → `Content.from_markup`. Measured: `[live] News` silently loses text, `[red]BBC[/red]` is styled, `[link=evil.example]click[/link]` becomes a terminal hyperlink, and `[/]` raises `MarkupError`. Provider and imported titles reach that path (`app.py` falls back to `view.title`; `local_snapshot` returns the document's own title). *Fix*: strip or escape `[`/`]` before assigning `border_title`/`border_subtitle`, and add a test with those four strings.

**[P0] Severity is computed and discarded, and stale looks fresh.** `render_metrics` never reads `Metric.severity`; `_add_row` applies severity styling only when `column.id == "state"`. So the Overview's Actions card draws "failed 1" exactly like "running 2", the Actions table shows "failure" and "success" in one tone, and Docker's `unhealthy 0` drops its warning. Meanwhile a card whose envelope is `expired` keeps full-brightness values. *Fix*: style metric values by severity; apply row severity generically; when freshness is not FRESH, render the title/freshness line in the warn tone and dim the values. Also give `border-subtitle-color` a palette token — it is currently Textual's default.

**[P1] The weather icons are not width-safe, and the metric padding measures characters.** `unicodedata.east_asian_width("⛅")` and `("☔")` are `W`, and Rich 15 computes `cell_len == 2` for both, VS15 or not. `render_metrics` pads with `pad = cell - (len(label) + 1 + len(value))` — character count, not cell width — so a thunderstorm row (`⛈︎`, 2 characters, 1 cell) starts one cell left of every other row. *Fix*: use only single-cell glyphs (drop the VS15 symbols), or pad with `rich.cells.cell_len`.

**[P1] Focus is the loudest channel while the boundaries are the quietest.** The focused card gets a 10.4:1 border; every other card border is 1.32:1 against the background, the held border 2.36:1, and the focused background lift 1.15:1 — decoration, not signal. `.sb-selected { border: heavy }` exists in the stylesheet and no code ever sets that class. On an iPad nobody is touching, the eye is pulled to the cursor instead of to the failing job. *Fix*: demote focus to a corner marker or accent tick, make severity the loudest channel, delete or implement `.sb-selected`.

**[P1] Dead space and identifier labels.** `apply_heights` gives every card 8–34 explicit rows and never fills the pane: Dev ends after 9+7 rows with ~15 empty, Life the same below YouTube; the modal is a fixed 90%×80% box with ~20 empty rows and its title is the raw widget id (`weather`, `portfolio`, `news`) while the card it came from said "Demo City". At the documented 60×20 minimum the inner card width is 56, so the item-meta branch (`width >= 60`) never renders and a seventh tab is clipped (six tabs already use 57 of 60 cells, and the strip does not scroll) — the docs' "six tabs are defaults, not a limit" does not hold there. *Fix*: distribute slack when the total estimate is under the viewport; `auto` height with `max-height` for the modal; pass the resolved card title into `DetailScreen`; require a human `label` on placed widgets instead of title-casing an identifier.

## Persona Red Flags

**Alex (impatient power user)**: no per-row action from a click — to open one HN link he must arrow to the row and press `o`; `n` ("advance") refuses on every tab except Overview ("Nothing rotating here"); long identifiers truncate at the tail, cutting exactly the ticket number ("feature/wbs-1129-location-settlement-po…"); the Sources table is un-sortable, un-filterable and shares a tab with his containers; toasts vanish with no history; `q` quits an always-on dashboard with one keypress; the only key on screen is `? help`.

**Sam (keyboard-only, low vision, screen reader)**: no roles or labels — a card's identity is a title inside a box-drawing border, so a screen reader reads border glyphs then bare label/value pairs with no "card 3 of 8" and no "this value is stale"; the pinned-card and saved-item markers are the same "◆"; nothing stops moving (`_on_status_tick` re-presents the active tab every second) and `space` pauses rotation only; unselected table rows are painted `sb-read` at 3.91:1 (below AA) because that token doubles as "not read"; the freshness text is the dimmest and smallest text on a card meant to be read at distance; palette cycling has no contrast floor and writes the choice to disk, so one stray keypress can persist a worse palette.

## Minor Observations

- `dim on panel` (the footer and chrome) is 4.4966:1 — it misses AA-normal by 0.0034; Catppuccin Mocha's is 3.36 and Gruvbox's 3.58.
- "◆" is overloaded: pinned card in the title, saved item in a row.
- "Sideboard" appears twice per screen (window title bar and footer).
- Cards cut at the fold show a sliced border with no "more below" affordance beyond the one-cell scrollbar.
- `render_status` prints "WARNING" in caps and, on a card with a body, draws it after a blank line at the bottom — the most important line in the least important position.
- `AI in digest` and `feeds` on the News card answer questions the card never asks.
- Empty tab state is "no widgets configured for this tab" — developer phrasing.
- `? help` sits in the far bottom-right corner, the least glanceable position on a 150-column screen.
- The theme picker's note is the one place explanatory prose survived the "no explanations" rule.

## Questions to Consider

1. If nobody's pointer and nobody's keyboard is near the iPad, what is "hover pauses rotation" for — should a slot stop rotating by default after N seconds, with rotation the exception?
2. Trust in the money cards depends on qualifiers that are themselves explanations ("priced 1/3", "missing quote"). What is the smallest qualifier that survives — a typographic mark on the value instead of a word?
3. Should the loudest signal be the data's severity rather than the keyboard's position? If both compete for one border colour, which loses?
4. What if freshness were a property of a value rather than a card, so each metric carried its own age?
